## Records and one-step reassessment

RecordStore requires an explicit approved independent root and an oq_ new session.
It never defaults to PRIVATE_ROOT or shares TaskService events/session.
TaskJournal construction creates directories, so even importing a later command
name does not authorize constructing it. A-S does not instantiate it.
The stable task_id/request_id key is separate from request_digest. Claim is
exclusive and fsynced before application core import. Same committed material
returns the verified old reference without computing; pending stops; changed
material at the same key rejects. No automatic cleanup, retry or takeover.

Artifacts precede the final Journal event; orphan artifacts remain uncommitted.
Existing TaskJournal removes its own transient writer lock by its original
finally behavior; pre-existing stale locks, partial logs, immutable claims and
orphan artifacts are never repaired by this wrapper. Those failures require
manual, separately approved recovery. Hash chains do not resist a privileged
same-owner rewriting all anchors. Directory fsync/OS crash durability is not
claimed. Parent decisions require an externally referenced committed event/hash
and unchanged task/environment/source/assets. A allows only root->one child,
new History/Snapshot and immutable old record; deeper/unknown ancestry rejects.
No TaskService dispatch, terminal-state reopen or real execution occurs.
