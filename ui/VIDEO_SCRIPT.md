# 3 分钟备份录像脚本

用途：现场演示失败时的备份片。UI 是备用，本脚本是备用的备用——两者都必须显示同一组数字。

**红线：片中出现的每个数字都必须来自当次真实执行。不要为了好看先写好字幕再补录，
也不要用上一轮的截图。录完立刻把终端里的 `运行目录` 和 `run_id` 一起剪进片尾，
让评委能核对这是哪一次跑出来的。**

---

## 0. 录制前 5 分钟检查

```bash
cd C:\h56demo                   # 恢复指南里的克隆根；用干净的克隆录，不要用开发树
git status --porcelain          # 必须为空
python -c "import sys;print(sys.version)"
python -B demo.py               # 主线 6 案例，约 5 秒，确认 6/6 与 6 条输入互不相同
python -B demo.py --compare-python <第二解释器>   # 确认 7 项 PASS
python -B -m ui.test_release_guards               # 12 项发布守卫
```

> 所有命令都带 `-B`。不带会在交付树里生成 `__pycache__`，`verify_pack.py` 会把它判成
> `EXTRA_FILE` —— 录完再验包会失败，且失败原因与演示无关。

- 分辨率 1920×1080，浏览器缩放 100%，关掉所有通知。
- 终端字号调到 16–18pt，背景纯黑，不要半透明。
- 先全流程空跑一遍计时，再正式录。主线约 5 秒、全量约 45 秒，不要剪掉等待段——
  等待本身就是「真实执行」的证据。

## 2. 备用台词（若现场被问）

**这一节按「会被问到」准备，不按「希望被问到」准备。承认的边界要主动说，不要等被追问。**

- 问「14 条拒绝是不是没做完？」→ 「恰恰相反。拒斥发生在写记录之前，所以那 14 条**没有**
  artifact，这是设计。您可以点开任一条看它的停止阶段和原因码。」
- 问「42 判定是不是 56 项能力？」→ 「不是，这个我已经在页面上分开了：56 行里 30 行是同一信封的
  重复运行，输入字节与基准完全相同，`semantic_sha256` 也一样；真实不同的输入 26 条，其中达到
  FEASIBLE 的只有 2 条。它们保留在回归基线里，用来暴露核心改动的 diff，不算独立能力。」
- 问「任务是不是大模型提出的？」→ 「不是。当前合同把任务来源钉死为合成字面量，接真实模型会被
  引擎自己的合同拒掉。演示里体现的是**判定侧**：外部提交证据包，OS 校验完整性，再依据事实与
  状态算候选；不满足就拒斥，未知就延后，满足就产出候选结论但永不授权。」
- 问「跨版本一致怎么证明？」→ 「性质 3：两个解释器各跑一次 C01，`semantic_sha256` 逐字节相同。
  屏幕上显示的是 3.9.13 vs 3.13.12。目前只证到 C01，不外推到全部案例。」
- 问「能不能直接执行？」→ 「不能，且这是被代码断言的边界，见第 7 项性质。
  `business_action_calls` 恒为 0。」
- 问「有没有故障注入 / 并发矩阵？」→ 「这一轮没做，README 的已知限制里列了。当前交付的主线是
  资格判定这条链的真实性，不是把每个边缘分支都铺满。」

## 3. 录制命令备忘

```bash
# 终端段
cd C:\h56demo
git log --oneline -2
python -B demo.py                                          # 演示主线（首选，画面干净）
python -B demo.py --all --compare-python C:\path\to\python313\python.exe   # 全量 + 跨版本

# 浏览器段（另开一个终端）
cd C:\h56demo
python -B ui\serve.py --compare-python C:\path\to\python313\python.exe
# 打开 http://127.0.0.1:8765/?open=1   ← open=1 让三个面板默认展开，省一次点击
```

素材存放：本机任意非仓库目录。**不要把 mp4/截图提交进仓库**——
它们会让 139 条清单之外的仓库体积和哈希讨论变得复杂，且不是交付必需项。
